# Itinerary mind map / 旅行思维导图标准

[简体中文](#简体中文) · [English](#english)

## 简体中文

用户选择导图时才用此标准。可单独交付，也可搭配 PDF、Excel 或文字攻略。

### 内容与布局

- 用一张从上到下读的树。根节点写旅行名、起止日和人数。目的地或阶段竖排，子气泡统一向右。每个实际旅行日独立成节点，格式如「6/26 周六 · 抵达」；同一目的地下面的 26、27、28、29 分开写。转场日放在主要行动所在阶段，可在下一阶段用关联线或跳转连接，避免两份信息分叉。
- 每日气泡首屏直接显示关键行动、当地时间、住宿及状态。展开或在右侧细节节点中保留适用的逐段交通、上车点、住宿、餐饮、活动、费用、预约、过敏或行动限制、备选和来源。以可读的长节点承载内容。按已确认的偏好、原攻略和最新修改逐项对照，确保导图与用户指定范围一致。
- 跨天事项单列，如签证、SIM、支付与防宰客、酒店和机票比价、预算、预订顺序、健康及装备。用文字状态配合颜色区分已确认、价格估算、班表线索、待确认和备选。跨分支连线只突出会改变安排的依赖，例如晚到影响早船、潜水后飞行或两段需分开订。
- 互动版支持单节点展开及全部展开；默认保留关键摘要可见。长内容能换行，节点和连线有间距，窄屏仍保留从左向右的层级。需要打印时检查分页与字号，必要时另做概览页。

### 可编辑交付与同一文件继续改

- 用户只想浏览，可交付互动浏览版。若要自己编辑、和助手轮流改或要求可编辑导出，交付真实可编辑的源文件。用户指定编辑器时，先验证可用导入、编辑和回存方式。可用 draw.io 时，默认用本地 `.drawio`，每个气泡和连线分别可编辑，保留文本和来源链接。现有 PDF、图片或浏览版仍可按用户要求作为查阅副本。
- **把打开方式一起交付。** 可提供经验证的可视化编辑入口，或明确给出「打开 draw.io → 文件 → 打开 → 设备 → 选择 .drawio」。源文件在通用预览器可能显示 XML。若编辑入口载入的是快照，说明编辑最新版应直接在编辑器打开用户保存的源文件。涉及个人行程的源文件留在用户指定位置，公开发布或分享另按用户要求处理。
- 用户改完保存回原路径后，以磁盘上的最新版为准。改动前读现有文件和用户手动修改，保留无关的节点、连线、布局和备注。改日期或项目时同步受影响的交通、住宿、预订、预算与其它在范围内的输出；校验后覆盖同名文件。若同时维护了编辑入口，按需要更新并核对是否载入最新版。
- 验收检查：日期齐全、节点有唯一标识、连线两端有效、文本与链接保留、预算及状态一致。条件允许时在实际编辑器打开并检查至少一个节点可改、连线可选、保存后可重新打开；若只做了结构验证，交付时说清验证范围。

## English

Use this standard only when the traveler selects a mind map. It can be delivered alone or alongside a PDF, spreadsheet, or text guide.

### Content and layout

- Make a top-to-bottom tree. Put trip name, dates, and party size at the root. Stack destinations or phases vertically and place every child bubble to the right. Give each travel date its own node, such as “Sat Jun 26 · Arrival.” Put a transfer day under its main action and cross-link the next phase when useful. Keep a single source of truth for the day's details.
- Show key actions, local times, overnight base, and status directly. Keep applicable transport legs and stops, lodging, food, activities, cost, booking, allergies or access needs, fallbacks, and evidence in expandable content or detail nodes to the right. Reconcile the map with the source itinerary, traveler decisions, and latest edits so it preserves the requested detail.
- Separate trip-wide checks such as visas, SIM, payments and fare pitfalls, hotel and flight quotes, budget, booking order, health and gear. Pair color with status text for confirmed, estimate, timetable lead, pending, and fallback. Use cross-links for dependencies that can change the plan, such as early ferries, separately booked legs, or flying after diving.
- In an interactive map, support expanding individual nodes and all details. Keep key summaries visible by default. Wrap long content and preserve the rightward hierarchy at narrow widths. Check text size and page breaks for print and provide an overview page when needed.

### Editable delivery and in-place revisions

- An interactive viewer is suitable for reading. For self-editing, shared revisions, or an editable export, deliver a genuinely editable source. When an editor is specified, verify that it can open, edit, and save the format. Where draw.io is available, default to a local `.drawio` with separately editable nodes and connectors and working source links. Offer a PDF, image, or viewer copy when requested.
- **Include a visual opening path.** Provide a verified editor launcher where practical, or explicit “draw.io → File → Open → Device → select the .drawio file” instructions. A generic preview may display XML. If a launcher opens a snapshot, explain how to open the latest saved source directly. Keep private trip files at the user's chosen location. Follow the user's scope for publishing or sharing.
- If the traveler saves back to the same path, read that latest file before editing. Preserve unrelated manual text, nodes, connectors, layout, and notes. Reconcile affected travel, stays, bookings, budget, and other outputs in scope. Validate before replacing the same file. Refresh and check the editor launcher when it is also in scope.
- Validate complete date coverage, unique node IDs, valid connector endpoints, preserved text and links, and consistent budgets and statuses. When possible, verify in the actual editor that a node can be edited, a connector selected, and the saved file reopened. State the verification scope when only the structure was checked.
